# F10: A disk that boots from the slot

**Group:** F. Recipes, graph, command

**Wave:** 10

**Needs:** F7, and Lemnos I5d (`lemnos-slot-init`)

**Runs:** board

Read `AGENTS.md` and `docs/design.md` first.

## Why

F7's `sd-image` is the bring-up form: it boots from an ext4 root partition and only carries the slot on the data partition. The real layout has no root partition and no A/B. A slot is an EROFS image with dm-verity, a file on the one ext4 data partition. A small initramfs opens it on a loop device, checks it with dm-verity and switches root. Each slot's kernel, device trees and initramfs are on the boot partition. The first-flash image carries one slot.

## Creates

- `recipes/slot-disk.toml` (or a mode of `sd-image`; say which in the PR and why)
- the nodes it needs (see Build)

## Read first

- Lemnos `docs/slots.md` and `service/slot-init` (the init program, and the kernel options it needs).
- The on-disk layout Lemnos's slot drivers manage: `/mnt/nvme-wd/lemnos-gates/I5-actions.md`, "On-disk layout and boot record". Match it exactly, so a first-flash image is one Lemnos can manage.

## Build

- **The disk:** the board's raw areas and partitions, a boot partition, the data partition. No root partition.
- **The data partition** (ext4):
  - `slots/<id>.erofs`: the image with its verity tree appended.
  - `slots/<id>.json`: its manifest, schema 3: `id`, `product` (lowercase, `[a-z0-9-]`), `version`, `variant` (optional), `board`, `kernel`, `display_name`, `image.size`, `image.sha256`, `verity.root_hash`, `boot.files`. `product` and `version` come from the product file, `board` from the board file's name. There is no `family` key.
  - `slots/<id>.boot`: one `<sha256>  <path>` line per boot file, the manifest included.
  - `slots/bootfiles/<sha256>`: the boot files, by content.
  - `board/slots/state.json` and `state.env`, naming the one slot as the default.
  - `slots/.incoming` is the slot driver's (0770, group `lemnos`). Leave it out.
  - The image's data component, if it has one.
- **The boot partition** (FAT, or what the board's loader reads):
  - `slots/<id>/`: the kernel, device trees, initramfs, `cmdline.txt` and `slot.json`.
  - The boot record, in the form the board's loader reads. Lemnos has three:
    - `tryboot`: `default.txt` and `trial.txt`, for firmware that reads them.
    - `uboot`, for a board whose loader is U-Boot:
      - `boot-record.env`, in `env import -t` text: `default=<id>`, `trial=<id>`, `trial_armed=0|1`.
      - `slots/<id>/extlinux/extlinux.conf` for each slot, in the form Lemnos's slot driver writes at install: the slot's own kernel, device tree and initramfs, and the command line below.
      - A root `extlinux/extlinux.conf` that copies the default slot's, for when the record cannot be read.
      - `boot.scr`: Lemnos's one static `packaging/uboot/boot.cmd`, compiled with `mkimage`. Gaia writes no script text.
      - The U-Boot build needs `sysboot`, `env import` and `env export`, `test`, and write support for the boot partition's filesystem. List the exact options in the PR; board files carry them.
    - `file`: one `boot-record` file, with one kernel and initramfs for every slot. The reduced mode, for a loader that can do neither.
  - The board file says which form its loader reads.
- **The kernel command line** in `cmdline.txt`: the image's own, then `<P>.slot=<id> <P>.roothash=<hex> <P>.data=PARTUUID=<uuid> panic=5`. `<P>` is a recipe parameter. The PARTUUID is the data partition's, which `gaia.disk` derives from the disk's id and the partition's name, so it is known before the disk is written.
- **The initramfs:** `initramfs-boot`, with `lemnos-slot-init` as a component. Gaia does not write the init program.
- **New nodes, as needed:** the manifest and the `.boot` list from the image, its verity table and the boot files; a text file from parameters and other steps' values (`cmdline.txt`, the state files); a tree from several artifacts (the boot partition's `slots/<id>/`). Each is generic: no slot, board or product name in code beyond the file names the layout fixes, and those are parameters with the layout's names as defaults.
- **The kernel** needs loop, EROFS and dm-verity built in. List the exact options from Lemnos's docs in the PR; board files carry them.

- **Size.** A raw image is as large as its content: no fixed free margin, and nothing empty written at flash. The data partition grows to the device on first boot, so the image says how (the partition is last, and the system or `lemnos-slot-init` grows it; say which in the PR). The recipe's output is the `.img.xz`, and it is the only build output: no slot pieces beside it. The build's output and `gaia plan` print each image's and slot's raw and compressed size.

## Proof

Board run: the ZERO 3E boots from the slot file. Paste the boot log lines where the initramfs opens the slot and verity is set up, `findmnt /` on the board, and `board/slots/booted`. Then Lemnos's slot driver lists the slot from the flashed image without changing any file. Paste the image's raw and compressed size, and how much of it is content. Report the board result to the coordinator for Lemnos's `testing/board-runs/I5d.md`: it is the first run of Lemnos's boot script on a board.
