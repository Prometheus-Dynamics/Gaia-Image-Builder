# F8: The OS and the board in the graph

**Group:** F. Recipes, graph, command

**Wave:** 8

**Needs:** D1, F5

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Why

A board's `[kernel]` and `[bootloader]` (sources, defconfig, fragments, device tree, bootloader blobs, trusted firmware) never reach the graph. An image names no OS. gaia-graph makes no `gaia.os.buildroot` node and derives nothing from the board. No recipe input carries the OS's root filesystem or its boot files. So no board image can be built. G2–G7 need this.

## Build

- **The image's OS.** `[[images]] os = { provider = "buildroot", source = "<a source>", fragments = [...] }`. Leave room for `import` and `none` (D4, D5).
- **Fragments derived from the board, in gaia-graph, by rule.**
  - The kernel: source repo and commit from the lock, defconfig, fragments, and the device tree with its directory as an external tree.
  - The bootloader: source, defconfig, fragments, trusted firmware (source, platform) and named blobs (`tpl`, …) by stored path.
  - The rules map description fields to Buildroot options. No board, SoC or vendor name appears in code; a board-specific value lives only in the board file. Board files are data Atlas owns for real boards, and Gaia only derives from them.
- **Pinned and visible.** Every source and blob is pinned by the lock. The derived fragments are text in the os step's key, and `gaia plan` lists them per image, the same way G8's host inputs are shown.
- **The root filesystem.** The OS's rootfs plus the image's component layers, merged with `gaia.tree.merge`, is what a recipe's `build` gets. Before this, `build` took exactly one built component.
- **Recipe input `os`.** The OS's boot files (`images/`: kernel, device trees, bootloader output) as a tree, for boot partitions and raw blobs.
- **Example.** `examples/products/zero-3e-demo` names a recipe that exists, not `ab-rootfs`. Gaia's slot model has no A/B.

## Proof

Paste: `gaia plan` for the ZERO 3E demo, with the derived fragments listed; a Buildroot build from them that produces the kernel, the dtb and `u-boot-rockchip.bin`; a fragment change that changes the os step's key.
