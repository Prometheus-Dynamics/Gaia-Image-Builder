# F9: Buildroot's downloads in the lock, and D2's caches on the os step

**Group:** F. Recipes, graph, command

**Wave:** 9

**Needs:** D2, F8

**Runs:** cloud

Read `AGENTS.md` and `docs/design.md` first.

## Why

D2 made the caches as nodes and rules: the download directory filled from locked files, a shared ccache, the reason for a clean build, and recovery from a killed make. F8 wires `gaia.os.buildroot` into the graph without them. Today, nothing writes Buildroot's own downloads into `gaia.lock`, and the os step's make output is gone when the step fails.

## Changes

`crates/bins/gaia` (lock), `crates/core/graph`, `crates/nodes/os-buildroot`.

## Build

- **The lock.** `gaia lock` records every file Buildroot downloads for an image's os config, with its digest: package, file and URL, the shape `gaia.os.buildroot.downloads` takes. An os config change without a re-lock is an error that says to lock.
- **The graph.** For each os step, the graph adds `gaia.os.buildroot.downloads` and the ccache fragment, both shown in `gaia plan`.
- **Resume.** The make's output directory outlives a failed step and is kept by the os step's key. When the step runs again with the same key, D2's `interrupted` rules apply. This is a node input, not a Gaia retry.
- **Clean builds.** A clean build names the options that forced it, in the run's output.

## Proof

Paste:
- a locked image built with the network off;
- the os step killed during make and run again, rebuilding only the package it was in;
- the reason printed for a config change.
