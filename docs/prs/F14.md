# F14: A flasher's outputs

**Group:** F. Recipes, graph, command

**Wave:** 12

**Needs:** F11

**Runs:** board

Read `AGENTS.md` and `docs/design.md` first.

## Why

A blank board is started by its boot ROM loading a bootloader into RAM, which takes a kernel and an initramfs over USB and boots them; from there flashing is an ordinary update. A flasher product needs outputs with no disk image, and today `initramfs-boot` has one input and one output and the built kernel and bootloader are thrown away. Atlas's draft flasher products list the fields.

## Build

- **Kernel and device trees as outputs** beside the initramfs (F11's split gives them).
- **A bootloader with its own fragments per image**: the flasher's needs USB fastboot and runs from RAM, the OS's does not (F11's split gives two builds from one source).
- **The raw bootloader file as an output**, for the step that sends it.
- **An Android boot image**, ready-made, for `fastboot boot`: kernel, initramfs and device tree, with the header version, page size and load addresses the flasher's bootloader accepts, as recipe parameters.
- **A FAT boot image** for the family whose USB boot loader serves one (kernel, device tree, initramfs, `config.txt`).
- The flasher uses the board's own kernel: one kernel per board. Its initramfs has no modules.
- The image is the only output where there is one; nothing is emitted beside it for convenience.

## Proof

Board run: a blank board is started and flashed with these outputs alone. Paste each output's size.
